# Component requirements documents

One CRD per design-system component: a `<component>.md` with every requirement and its
Given/When/Then acceptance criteria, and a `<component>.html` that renders the component in every
variant, size and state, in light and dark, with the design system's own stylesheets. Written with the
`writing-component-requirements-documents` skill. Read the component's CRD before building or
changing it; when an L2 requirement changes, the *L2 trace* column lists every component it affects.

Status: `built` means the component exists in `frontend/projects/components`; `planned` means it does not
yet. A mixed status names the built part.

Check the folder with:

```sh
python3 .claude/skills/writing-component-requirements-documents/scripts/check_crds.py docs/specs/components
```
