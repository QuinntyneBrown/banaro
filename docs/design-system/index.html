Visual language · v1.0

Banaro design system

A calm visual language for Christian product builders in Toronto and the GTA.

Foundations

Color

The surface palette is warm and quiet. Sage highlights the main decision; clay and fjord distinguish initials tiles. Roles, not literal values, decide which colours touch.

Typography

Manrope carries every product role; JetBrains Mono is reserved for code. Body text remains 16px with a relaxed 1.65 line height, while display headings use light weight and tight tracking.

Spacing

Use the shared spacing steps inside components and between sections. Half-step 2px is reserved for fine control geometry; primary layout gaps use whole 4px multiples.

Layout

The content cap is 74rem, with 4, 8 and 12 columns. Margins and gutters grow at 768px and 1024px. These values preserve the selected design rather than substituting a generic grid.

Elevation

The system has four warm, soft shadows. Use level 1 for subtle separation, level 2 for resting cards, level 3 for hover and toasts, and level 4 for overlays.

Shape

Use the existing five rounded steps plus a pill sentinel. Medium corners are normalised from 14px to 16px; portrait identity remains square with rounded corners.

Motion

Motion explains continuity: 240ms colour feedback, 420ms hover movement, 640ms overlay entrance and 900ms photographic emphasis. Avoid motion that delays access.

Iconography

The mock icons use a 24-unit viewBox, rounded joins and currentColor. Default display is 20px and the compact form is 16px; the line stroke is 1.5 units.

Theming

Set data-theme on a root or specimen wrapper. Light uses oat and birch; dark uses warm charcoal. Native controls inherit color-scheme so they follow the same choice.

Responsive

The same information and reading order work at 360px, 768px and 1280px. The shared grid changes at 768px and 1024px; the sheet threshold is 640px.

Accessibility

Native elements provide names, roles and values. Every component page documents keyboard use, focus, labelling, contrast, motion and touch. Verified contrast is evidence for one part of accessibility, not a full conformance certification.

Content

Speak as a local builder inviting another person to build together. Faith is part of the community’s purpose; product copy stays concrete and welcoming.

Components

Button

Trigger one action: join, save, say hello, RSVP or confirm a deletion. Keep one primary action in each action group.

Button group

Keep closely related actions or exclusive choices together. Use a fieldset for form answers.

Link

Navigate to a builder, project, event or help page. Use a button for operations.

Menu

Group secondary profile/account actions. The mocks show both navigation lists and action menus: only action menus need menu roles.

Text field

Collect short answers in join, profile and matching forms. Prefixes and suffixes explain units without replacing labels.

Textarea

Write a bio, project description or private introduction. Keep long text editable after failures.

Select

Choose sort order, stage or neighbourhood from a short closed list.

Checkbox

Select multiple roles, skills or interests independently. A fieldset legend supplies the shared question.

Radio group

Choose one role, preferred distance or matching goal.

Switch

Turn an ongoing preference on or off, such as event reminders or matching availability.

Slider

Adjust matching distance, paired with a numeric alternative.

File upload

Choose a profile photo. Dragging is an enhancement to a native labelled file input.

Form field

Keep an answer and its explanation together. The wrapper supplies vertical rhythm and label associations.

Form layout

Compose account, project and matching forms from shared fields. Validate on blur, revalidate corrected fields on input.

Top bar

Anchor Banaro navigation and account access. The public header and signed-in header use the same destinations.

Sidebar navigation

Navigate settings subpages or directory refinements. Keep page navigation separate from field choices.

Tabs

Switch local panels. Matching route links use aria-current; actual local tabs use tab/tablist/tabpanel.

Breadcrumb

Show the parent path on builder, project and event detail screens.

Pagination

Move through stable directory result sets. Load more preserves current items while busy.

Stepper

Explain onboarding and matching setup progress. It does not submit answers by itself.

Footer

Close public pages with consistent help, privacy and community links.

Skip link

Let keyboard users skip repeated navigation. It is the first focusable control.

Card

Show one builder with enough information to assess local collaboration. Whole-card styling does not replace the real name link.

Accordion

Reveal secondary information. Native details is appropriate for independent disclosures, including the profile More section.

Dialog

Ask for a focused decision or short edit. Destructive actions name the object and explain consequences before confirmation.

Drawer and sheet

Expose directory filters on narrow screens while keeping context. A modal drawer shares dialog focus rules.

Popover

Show a short nonmodal set of controls. Browser popovers dismiss on Escape and outside click; interactive content needs a labelled trigger.

Tooltip

Explain a compact icon only when the visible layout cannot carry the label. A tooltip supplements the accessible name.

Divider

Separate menu groups or sections, using a decorative line when semantics are unnecessary.

Container, grid and stack

Compose responsive screens with the extracted 4/8/12-column grid. Preserve the mock’s generous spacing.

Table

Compare structured data when a card list would obscure relationships. This is a core extension; current mocks primarily use lists.

List

Render projects, events, conversations and activity in reading order.

Description list

Present builder facts, project stage, skills and matching reasons.

Avatar

Identify builders in profiles, cards and conversations. Keep the mock’s softly rounded square rather than circles.

Badge and status

Show project stage, RSVP state or unread count. Colour supplements words.

Chip and tag

Select skills and show applied directory filters. Static tags summarize skills; removable tags have a separate remove button.

Stat and KPI

Summarize builder counts, demos and RSVP capacity. Numbers use tabular figures; deltas include signs and words.

Code block

Show implementation examples and token usage in documentation. This is a core documentation extension.

Timeline and activity

Show recent building activity or grouped notifications. Use ol for chronology; a notification list is not an APG infinite feed.

Toast

Confirm a brief completed action while keeping the user on the current screen. Errors persist until resolved or dismissed.

Alert and banner

Explain persistent page or field problems, offline status and account verification. Important new failures may use alert; already-visible content stays passive.

Inline message

Give help near an input or report a small outcome beside its action.

Progress bar

Show known upload or setup progress. Indeterminate progress omits aria-valuenow.

Spinner

Indicate a short local operation inside its action. Use skeletons for content loads and progress for known completion.

Skeleton

Reserve the actual future card or row layout while loading.

Empty state

Explain an empty dashboard, no matching builders or an unavailable collection while preserving navigation.

Error page

Keep a route recoverable when content is missing, forbidden or temporarily unavailable.

Brand

Identify the local builder community consistently. The brand links to Home.

Page header

Introduce a routed screen and the action it exists for.

Hero

Introduce Banaro’s faith-aligned local purpose with restrained imagery.

Feature area

Describe Banaro’s four core areas without turning the page into a dense dashboard.

Featured builder

Show compact builder identities on Home and event compositions.

Project card

Share work in progress, not a fundraising pitch. Preserve the object, ask and stage.

Event row

Show Toronto/GTA gatherings in chronological rows.

Testimonial and verse

Support community trust with real copy and an identifiable source.

Matching invitation

Explain why a local collaborator may be relevant and give an intentional next step.

Search and filter toolbar

Refine the builder and project directory without losing context.

Profile header

Let readers assess a builder’s craft and availability before making contact.

Message thread

Show private introductions with visible delivery and recovery.

Inbox

Choose a conversation before reading its thread.

Notification item

Show updates people can revisit after a toast disappears.

Feedback comment

Show focused product feedback in a readable conversation.

Project screenshot

Show what the product currently does, with an informative caption.

RSVP panel

Make event attendance and capacity understandable before a commitment.

Danger zone

Present account or project deletion with the scope of loss plainly stated.

Prose and legal content

Present About, Privacy and Code of conduct content with the same calm typography.

Patterns

Forms

Collect a clear answer, preserve it, and explain the next step.

Feedback and loading

Choose feedback by what changed and how long it matters.

Empty and error states

Keep the task understandable when content is absent.

Navigation and page structure

Keep destinations, hierarchy and reading order predictable.

Dialogs and overlays

Ask for a focused decision without losing the page context.

Data tables and lists

Make comparison and browsing readable at every width.

Notifications

Choose a channel by urgency and how long the information matters.

Content and tone

Use concrete, welcoming copy for builders nearby.

How to use

  1. Choose a foundation role before choosing a component.
  2. Use the BEM classes and documented native state semantics.
  3. Read each component’s keyboard and responsive rules before implementing behavior.
  4. Link tokens.css and components.css; use tokens.json for portable design tooling.
  5. Keep mocks consuming the same files so the design and implementation have one vocabulary.
