When

Use forms for account setup, project editing and matching preferences. Short button-triggered editing belongs in a dialog; long editing belongs on a screen.

Structure

Group related fields with a fieldset and legend. Put a visible label above each input, followed by help. Use a linked summary on failed submit and one primary action after safe actions.

States

Default → touched/invalid → submitting → success or recoverable failure. Validate on blur, revalidate corrected fields on input; keep typed data and attach the error to the field.

Responsive

One column on phones. At 768px pair short related answers; keep a description textarea full width.

Accessibility

Move focus to the error summary after submit failure. Keep aria-invalid and aria-describedby on the exact field. Do not disable every form element while preserving only an unnamed spinner.

Content

Say what will happen: Create account, Save project or Send introduction. Explain required answers and who can see profile data.
