Principles

Native elements provide names, roles and values. Every component page documents keyboard use, focus, labelling, contrast, motion and touch. Verified contrast is evidence for one part of accessibility, not a full conformance certification.

Perceivable

Keep text, icon and label alternatives. Reflow long content; preserve information when colour is unavailable. Respect user text spacing, contrast preferences and reduced motion.

Operable

Keep all actions reachable by keyboard, show focus and avoid covering it with sticky chrome. Use a first-focusable skip link. Provide single-pointer alternatives to drag actions; let people pause or dismiss timed updates.

Understandable

Use visible labels and correction instructions; retain entered answers after failures. Confirm consequential deletion, allow paste/password managers, and keep help and navigation in consistent locations.

Robust

Prefer native controls. Reserve ARIA for missing semantics and implement the keyboard model whenever a widget role is used. Announce routine status politely and new urgent failures sparingly.

Reference: WCAG 2.2 and WAI-ARIA Authoring Practices.
